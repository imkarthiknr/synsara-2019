## Prerequisites

- Python 3.11 or newer (3.13 is pinned in `.python-version`)
- [uv](https://docs.astral.sh/uv/) for dependencies and running commands
- Optional: Docker with Compose v2, to run with PostgreSQL
- Optional: Node.js with Playwright, for the browser walkthrough

## Setup

```bash
uv sync                          # creates .venv with app + dev dependencies
cp .env.example .env             # optional; every setting has a local default
uv run alembic upgrade head      # creates data/synsara.db
uv run python -m app.seed        # optional: 12 fictional participants, 2 teams
uv run uvicorn app.main:app --reload
```

Open <http://localhost:8000>. The organiser console is at `/admin` (`admin` / `synsara-admin` unless you changed them). The app logs a warning at start-up while the default secret key or admin password is in use.

## Configuration

Settings are read from environment variables or `.env` by [`app/core/config.py`](app/core/config.py).

| Variable | Default | Purpose |
| --- | --- | --- |
| `DATABASE_URL` | `sqlite:///./data/synsara.db` | SQLAlchemy URL. Use `postgresql+psycopg://user:pass@host/db` for PostgreSQL |
| `SECRET_KEY` | development value | Signs the session cookie. Must be long and random in production |
| `ADMIN_USERNAME` / `ADMIN_PASSWORD` | `admin` / `synsara-admin` | The organiser login |
| `COOKIE_SECURE` | `false` | Set `true` behind HTTPS so the cookie is only sent over TLS |
| `REGISTRATION_OPEN` | `true` | `false` shows a "registrations closed" page instead of the forms |
| `UPLOAD_DIR` | `./data/uploads` | Where hackathon abstracts are stored. Keep it outside `app/static` |
| `MAX_UPLOAD_MB` | `5` | Abstract size limit |
| `SYNSARA_CONTENT` | `content/synsara-2019.yaml` | The edition's content file |

## Database, migrations and demo data

The schema is in [`app/models.py`](app/models.py):

| Table | Holds |
| --- | --- |
| `participants` | One row per person. E-mail and mobile are unique. The public ID is `SYN19-` plus the zero-padded row ID |
| `event_entries` | Which events each participant chose (`participant_id`, `event_slug`), unique per pair |
| `hackathon_teams` | Leader details, project, preferences and the stored abstract's random file name. Public ID `HUM19-001` |
| `team_members` | The other team members, in order |

Events are not a table: an entry stores the event's `slug` from the content file. Don't rename a slug once registrations have started.

Migrations live in `migrations/` and run the same way on SQLite and PostgreSQL (SQLite uses Alembic's batch mode).

```bash
uv run alembic upgrade head                            # apply
uv run alembic revision --autogenerate -m "add x"      # after changing models.py
uv run alembic check                                   # fails if models and migrations differ
uv run alembic downgrade -1                            # undo the last one
```

Review autogenerated migrations before committing; Alembic can't detect renames. `python -m app.seed` adds fictional demo registrations through the same service functions as the forms, and does nothing if they're already there.

## Content file

[`content/synsara-2019.yaml`](content/synsara-2019.yaml) describes the edition: name, dates, venue, prize pool, contact e-mail, the registration rules, each event (category, logo, teaser, team size, description, rounds, rules), the hackathon with its FAQ and abstract template, the workshop and sponsors. [`app/content.py`](app/content.py) validates it with Pydantic when the app starts, so a typo such as a duplicate slug or an unknown category stops the app with a clear error instead of breaking a page.

To run another edition, copy the file, edit it and point `SYNSARA_CONTENT` at it. Logos go in `app/static/img/events/` (WebP, about 256×256). An event with `logo: null` shows its initial instead.

## How a request flows

```
app/main.py           create_app(): session middleware, security headers, static files, error pages
app/web/public.py     GET/POST routes for the public site and the forms
app/web/admin.py      organiser routes, all behind require_admin
app/web/common.py     render(), CSRF helpers, flash messages, form error mapping
app/schemas.py        Pydantic models for form fields (types, lengths, mobile format)
app/services/         rules that need the database or the content file
app/models.py         SQLAlchemy models
```

A form POST goes through four steps: `verify_csrf`, Pydantic validation of the fields, a service call that applies the edition's rules, then a `303` redirect to a "done" page (post/redirect/get, so a refresh doesn't resubmit). Errors re-render the form with status `422`, the entered values and a message next to each field. Services raise `RegistrationError(message, field)` so the route knows where to show it.

Pages are server-rendered with Jinja2. Templates are in `app/web/templates/`; shared form macros are in `partials/forms.html` and must be imported `with context` because they read the request.

## Registration rules

Implemented in [`app/services/registrations.py`](app/services/registrations.py) and [`app/services/hackathon.py`](app/services/hackathon.py), with limits from the content file's `rules` section:

- A participant picks at least one event, at most `max_technical` technical and `max_non_technical` non-technical events, and only events that exist in that category.
- E-mails (case-insensitive) and mobile numbers are unique among participants, and separately among team leaders.
- With `hackathon_is_exclusive`, an e-mail used for a hackathon team can't register for events, and the other way round.
- A team has `hackathon_team_min` to `hackathon_team_max` people including the leader. Team names are unique, ignoring case.
- An abstract must be a real PDF (`%PDF-` header) or DOCX (a zip containing `word/document.xml`), whatever its extension, and no larger than `MAX_UPLOAD_MB`. It's saved as `<random hex>.pdf|docx`; the cleaned original name is only used for display.

The JavaScript on the registration form disables extra checkboxes once a limit is reached, but the server never relies on it.

## Security model

- **Organiser auth:** one account from the environment, compared with `hmac.compare_digest`. A successful login clears and re-creates the session. The cookie is signed (`SECRET_KEY`), `HttpOnly`, `SameSite=Lax`, expires after 8 hours and is `Secure` when `COOKIE_SECURE=true`. The `next` redirect only accepts `/admin` paths.
- **CSRF:** each session gets a random token; every POST form includes it and the server checks it with a constant-time comparison.
- **Headers:** a strict Content Security Policy (`default-src 'self'`, no inline scripts or styles), `X-Frame-Options: DENY`, `nosniff` and a referrer policy on every response. Keep it that way: put styles in `site.css` and scripts in `site.js`, never inline.
- **Uploads:** stored outside the static folder, served only to organisers with `Content-Disposition: attachment`, `nosniff` and `no-store`. The service also checks that the resolved path is inside `UPLOAD_DIR`.
- **Exports:** spreadsheet cells that start with `=`, `+`, `-` or `@` get a leading `'` so Excel won't run them as formulas.
- **Data:** the repository holds no personal data. The demo seed uses `example.com` addresses and made-up numbers.

## Frontend

No build step. [`app/static/css/site.css`](app/static/css/site.css) holds the design tokens (`--bg`, `--neon`, …) and all styles; [`app/static/js/site.js`](app/static/js/site.js) adds the text scramble, the countdown, the mobile menu, the checkbox limits and delete confirmations. Everything works without JavaScript except those enhancements. Animations are turned off for users who prefer reduced motion.

Exo 2 is self-hosted as WOFF2 in `app/static/fonts/`, converted from the 2019 OTF files without changes, under the SIL Open Font License ([`OFL.txt`](app/static/fonts/OFL.txt)).

## Testing

```bash
uv run pytest                     # all tests, SQLite
uv run pytest tests/test_rules.py -k team
TEST_DATABASE_URL=postgresql+psycopg://synsara:synsara@localhost/synsara_test uv run pytest
```

| File | Covers |
| --- | --- |
| `test_content.py` | The content file loads, logos and the template exist, duplicate slugs are rejected |
| `test_rules.py` | Event limits, duplicates, mobile normalisation, team size, upload sniffing and size, file storage, hackathon exclusivity |
| `test_public.py` | Pages, prefill, CSRF, validation errors, registration closed, hackathon upload, security headers, 404 |
| `test_admin.py` | Login, open redirect guard, lists, delete, Excel sheets and the formula guard, CSV, abstract download, demo seed |
| `test_migrations.py` | Migrations apply, match the models and downgrade cleanly |

`tests/conftest.py` gives each test a fresh database and its own upload folder, and sets test credentials. Use `csrf_of(client, path)` to get a form token and `login(client)` to sign in as an organiser.

A Playwright walkthrough of the main journeys (prefill, checkbox limits, registration, duplicate check, hackathon upload, exclusivity, organiser login, Excel and abstract downloads, mobile layout) was used to check the UI and take the screenshots in `docs/screenshots`.

## Code style

[Ruff](https://docs.astral.sh/ruff/) handles linting and formatting (line length 100, rules in `pyproject.toml`):

```bash
uv run ruff check . --fix
uv run ruff format .
```

Type hints on public functions, SQLAlchemy 2 typed models, and short docstrings where the reason isn't obvious from the code.

## Continuous integration

[`.github/workflows/ci.yml`](.github/workflows/ci.yml) runs on pushes to `master` and on pull requests:

1. **lint**: `ruff check` and `ruff format --check`
2. **test**: pytest on Python 3.11 and 3.13 (SQLite)
3. **postgres**: migrations up, `alembic check` and down against PostgreSQL 17, then pytest on PostgreSQL
4. **docker**: builds the Compose stack, waits for health checks, smoke-tests the pages and registers a participant through the real form with curl

## Docker

The [`Dockerfile`](Dockerfile) installs locked dependencies with uv, runs as a non-root user and stores uploads in the `/app/data` volume. [`docker/entrypoint.sh`](docker/entrypoint.sh) runs `alembic upgrade head` before starting uvicorn, so the schema is always current. `docker-compose.yml` adds PostgreSQL with a health check and named volumes for the database and uploads.

```bash
docker compose up --build -d
docker compose exec web python -m app.seed
docker compose logs -f web
docker compose down            # add --volumes to delete the data too
```

## Common tasks

| Task | How |
| --- | --- |
| Add or edit an event | Edit the content file (and add a logo); restart the app |
| Close registrations | `REGISTRATION_OPEN=false` |
| Change the event limits or team size | `rules:` in the content file |
| Add a form field | Model column + migration, `schemas.py`, the template, the export row in `services/exports.py`, a test |
| Download everything | `/admin/export.xlsx`, or `/admin/participants.csv` |
| Reset local data | Delete `data/` and run `alembic upgrade head` again |

## Troubleshooting

| Problem | Fix |
| --- | --- |
| `no such table: participants` | Run `uv run alembic upgrade head` |
| `400` "Your session expired" on a form | The session cookie changed (new `SECRET_KEY` or expired). Reload the form and submit again |
| Login works but you're sent back to the login page | `COOKIE_SECURE=true` over plain HTTP. Set it to `false` locally |
| The app won't start with a content error | The message names the field; fix the YAML (often a duplicate slug or a wrong `category`) |
| An abstract is rejected although it's a PDF | It's probably a renamed file or over the size limit; export it again as PDF |
| `alembic check` fails | Models changed without a migration. Autogenerate one and review it |
